# Windows Class Monitoring

Фоновый мониторинг заряда ноутбуков Windows через Яндекс Диск. Каждый компьютер раз в **5 минут** отправляет своё имя, заряд, состояние питания и версию агента. Один HTML-дашборд показывает все устройства.

**Python 3.10+ • Windows 10/11 • без сторонних Python-библиотек • обновление через Git.**

## Установка на ноутбук

Установите [Git for Windows](https://git-scm.com/downloads/win) и [Python](https://www.python.org/downloads/windows/) с Python Launcher (`py`). Затем выполните в обычном PowerShell под тем пользователем, от которого будет работать агент:

```powershell
git clone https://github.com/meshcheryakovaa/windows_class_monitoring.git C:\BatteryMonitor
cd C:\BatteryMonitor
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1
```

Установщик спросит название, интервал, токен и предложит включить автозапуск. Сторонние пакеты и виртуальное окружение не требуются. По умолчанию используется системное имя компьютера, интервал — 300 секунд.

Агент работает без окна через `pythonw.exe`. Управление — через CLI; значок в трее в версии 1.0 не предусмотрен. Автозапуск выполняется **при входе текущего пользователя** через Планировщик заданий, включая работу от батареи. До входа в Windows и после выхода из учётной записи агент не работает. Это пользовательское приложение, не системная служба.

Если политика организации запрещает пользовательские задачи Планировщика, зарегистрировать автозапуск должен администратор. Остальные команды можно использовать без регистрации задачи.

## Подключение Яндекс Диска

1. Создайте приложение в [Яндекс OAuth](https://oauth.yandex.ru/).
2. Укажите Redirect URI: `https://oauth.yandex.ru/verification_code`.
3. Добавьте разрешение **доступа к папке приложения на Яндекс Диске** — `cloud_api:disk.app_folder`.
4. Скопируйте Client ID и выполните:

```powershell
.\battery.ps1 auth --client-id ВАШ_CLIENT_ID
```

Откроется браузер. Разрешите доступ и скопируйте токен. Если он указан в адресе после `#access_token=`, копируйте только его значение до следующего `&`. Вставьте токен в скрытый запрос CLI.

Если токен уже получен:

```powershell
.\battery.ps1 auth
```

**Все ноутбуки и дашборд должны использовать один аккаунт Яндекса и одно OAuth-приложение.** У разных OAuth-приложений разные папки `app:/`, даже в одном аккаунте. Допускаются отдельные токены одного приложения для устройств. Файлы не нужно публиковать или открывать по публичной ссылке.

Агент проверяет новый токен до сохранения; неудачная проверка сохраняет прежнее подключение. Токен шифруется Windows DPAPI для текущего пользователя. Его нельзя переносить на другой компьютер копированием `token.dat`: на новом устройстве выполните `auth`. Автоматическое обновление истёкших OAuth-токенов в этой версии не выполняется — повторите `auth`.

Для автоматизированной настройки есть `auth --stdin`. Передавайте токен из менеджера секретов через stdin; не записывайте его литералом в историю команд или Git.

Официальная документация: [получение токена вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token), [REST API Диска](https://yandex.ru/dev/disk/rest/).

## Команды управления

Все команды ниже выполняются в `C:\BatteryMonitor`. Справка также доступна через `help` и `--help` у отдельных подкоманд.

| Команда | Действие |
| --- | --- |
| `.\battery.ps1 setup` | Пошаговая настройка, автозапуск и запуск |
| `.\battery.ps1 start` | Запустить без окна; второй экземпляр не запускается |
| `.\battery.ps1 stop` | Корректно остановить, дождавшись текущего сетевого запроса |
| `.\battery.ps1 restart` | Перезапустить |
| `.\battery.ps1 status` | Состояние процесса, текущий заряд, последняя отправка и ошибка |
| `.\battery.ps1 status --json` | Машиночитаемое состояние |
| `.\battery.ps1 config show` | Настройки; токен не выводится |
| `.\battery.ps1 config show --json` | Настройки в JSON |
| `.\battery.ps1 auth` | Скрытый ввод и проверка токена |
| `.\battery.ps1 test` | Проверка батареи и доступа к Диску, без загрузки файлов |
| `.\battery.ps1 test --json` | Результат проверки и образец измерения в JSON |
| `.\battery.ps1 send` | Немедленно отправить измерение |
| `.\battery.ps1 logs` | Последние 50 строк журнала |
| `.\battery.ps1 logs --follow` | Смотреть журнал до Ctrl+C |
| `.\battery.ps1 logs --bootstrap` | Ошибки запуска фонового процесса |
| `.\battery.ps1 autostart enable` | Зарегистрировать запуск при входе текущего пользователя |
| `.\battery.ps1 autostart disable` | Удалить задачу автозапуска; агент не останавливается |
| `.\battery.ps1 autostart status` | Проверить регистрацию автозапуска |
| `.\battery.ps1 dashboard` | Открыть HTML-панель |
| `.\battery.ps1 update` | Проверить новую версию, обновить через Git, перезапустить |
| `.\battery.ps1 version` | Версия установленного кода |
| `.\battery.ps1 help` | Справка |

Успешные команды возвращают код `0`, ошибки — `1`, прерывание Ctrl+C — `130`. При неверных CLI-аргументах возвращается `2`. Поля JSON используют `snake_case`.

### Изменение настроек

```powershell
.\battery.ps1 config set display-name "Ноутбук 12"
.\battery.ps1 config set interval 300
.\battery.ps1 config set disk-path "app:/windows-class-monitoring/devices"

# Вернуть системное имя / стандартный интервал / стандартную папку
.\battery.ps1 config reset display-name
.\battery.ps1 config reset interval
.\battery.ps1 config reset disk-path
```

Интервал: от 30 до 86400 секунд. Работающий агент сам применяет изменения примерно за секунду, после завершения текущего запроса. Изменение папки не удаляет прежние файлы на Диске; выберите ту же папку в настройках дашборда.

## HTML-дашборд

Откройте `dashboard.html` в обычном Chrome, Edge или Firefox либо выполните:

```powershell
.\battery.ps1 dashboard
```

Нажмите **«Подключить Диск»**, вставьте токен того же OAuth-приложения и оставьте стандартную папку. Client ID необязателен: он нужен только для кнопки получения токена.

Возможности панели:

- Карточки с названием, системным именем, процентом заряда, питанием, временем измерения и версией агента.
- Поиск, сортировка по заряду / названию / времени, фильтры.
- Сводка по устройствам, свежим данным и ноутбукам, которым нужно питание.
- Красный статус при заряде **ниже 20%**, если ноутбук работает от батареи и данные свежие.
- Серый статус после **15 минут** без измерений; при интервалах больше 5 минут — после трёх интервалов.
- Автообновление панели раз в минуту, ручное обновление и полноэкранный режим.
- Демонстрационный режим без подключения: данные в нём явно помечены как вымышленные.

Панель читает список файлов с пагинацией, скачивает только изменившиеся и делает не больше трёх скачиваний одновременно. При временной ошибке сохраняет предыдущие показатели и сообщает о проблеме. Токен находится **только в памяти вкладки**: после перезагрузки его нужно ввести снова. В браузере сохраняются только папка и Client ID. Панель работает, пока открыта вкладка; браузер может замедлять таймеры неактивных вкладок.

Если локальный `file://` блокируется браузером, попробуйте локальный HTTP-сервер:

```powershell
cd C:\BatteryMonitor
py -3 -m http.server 8765 --bind 127.0.0.1
```

Откройте [http://127.0.0.1:8765/dashboard.html](http://127.0.0.1:8765/dashboard.html). Сервер остановится по Ctrl+C. Он привязан к вашему компьютеру, не к локальной сети. Если блокировку CORS накладывает сам API или политика организации, смена `file://` на HTTP её не отменит; потребуется разрешённый браузер/источник или отдельный локальный прокси. Отключать защиту браузера не нужно.

## Обновление через Git

```powershell
cd C:\BatteryMonitor
.\battery.ps1 update
# Или:
.\update.ps1
```

Обновление:

1. Проверяет отсутствие локальных изменений и наличие upstream-ветки.
2. Выполняет `git fetch --prune`, проверяет возможность fast-forward.
3. Проверяет Python-код и тесты новой версии во временном Git worktree **до остановки агента**.
4. Останавливает агент, выполняет `git pull --ff-only`.
5. Запускает новый код, если агент работал до обновления. Остановленный агент остаётся остановленным.

При ошибке до изменения кода прежний агент продолжает работу или запускается снова. Если удалённая ветка изменилась между проверкой и `pull`, установленный код проверяется повторно. При ошибке проверки изменённого кода агент остаётся остановленным: принудительный сброс Git и потеря локальных правок не выполняются. Настройки не затрагиваются.

Можно обновлять и вручную:

```powershell
.\battery.ps1 stop
git pull --ff-only
.\battery.ps1 start
```

Просто `git pull` меняет файлы; работающий процесс продолжит использовать старый код до перезапуска. Панель после обновления обновите в браузере. Авторизация на GitHub нужна только если репозиторий станет приватным. Устройство, на котором используется `update`, должно оставаться Git-клоном, а не распакованным ZIP.

## Хранение и протокол

На устройстве: `%LOCALAPPDATA%\WindowsClassMonitoring\`.

| Файл | Содержимое |
| --- | --- |
| `config.json` | Постоянный UUID устройства, название, интервал, облачная папка |
| `token.dat` | Токен, защищённый Windows DPAPI |
| `status.json` | Последняя попытка, последняя успешная отправка, ошибка, версия процесса |
| `agent.log` | Журнал с ротацией: до 4 файлов примерно по 1 МБ |
| `bootstrap.log` | Ошибки последнего запуска через `pythonw` |
| `agent.lock`, `*.request` | Блокировка экземпляра и сигналы управления |

В Git нет пользовательских настроек и токенов. Скопируйте код на другой компьютер через `git clone`, затем выполните `setup` — будет создан отдельный UUID. Не копируйте каталог пользовательских данных между ноутбуками. После переустановки с удалением этих данных появится новый UUID; старую карточку можно убрать, удалив соответствующий JSON на Диске.

В облаке: `app:/windows-class-monitoring/devices/<device_id>.json`. `app:/` — специальный путь папки OAuth-приложения. Каждый агент перезаписывает только свой файл; общей базы с конфликтующими записями нет. История измерений не накапливается. Пример:

```json
{
  "schema": "windows-class-monitoring/v1",
  "device_id": "b98446bf-88ca-47cf-8bca-81aac105729c",
  "computer_name": "CAB43-NB12",
  "display_name": "Ноутбук 12",
  "agent_version": "1.0.0",
  "os": "Windows-11",
  "measured_at": "2026-10-23T16:00:00Z",
  "interval_seconds": 300,
  "battery_present": true,
  "battery_percent": 42,
  "ac_connected": false,
  "charging": false,
  "remaining_seconds": 7200
}
```

Неизвестные значения — `null`, а не 0. Состояние «подключено питание» отличается от «идёт зарядка»: при полном аккумуляторе зарядки может не быть. Время работы — оценка Windows и может отсутствовать. Стационарный ПК показывается без батареи.

Данные передаются через HTTPS, но сам JSON дополнительно не шифруется. Агент не принимает удалённые команды, не снимает экран и не передаёт файлы пользователя. Для свежести данных нужны корректные часы на ноутбуках. Статус «нет свежих данных» не означает точно «выключен»: возможны сон, потеря сети и ошибки авторизации.

После сна агент отправляет новое измерение. При ошибке сети/Диска повторяет отправку максимум раз в минуту (при интервале менее минуты — по заданному интервалу); после успешной отправки возвращается к обычному расписанию. Пропущенные измерения не накапливаются, ноутбук не пробуждается специально.

## Разработка и проверка

```powershell
py -3 -m unittest discover -s tests -v
node --test tests/dashboard.test.cjs
```

Node.js нужен только для тестов панели, для использования приложения он не нужен. GitHub Actions запускает проверки на Windows и Linux с Python 3.10 и 3.13. На Windows дополнительно проверяются настоящие DPAPI и API питания, синтаксис PowerShell и запуск CLI. Тесты не требуют OAuth-токена и не загружают данные на Диск. Реальная работа с Диском проверяется пользователем через `auth`, `test` и `send`.

Системный API: [GetSystemPowerStatus / SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status). Защита токена: [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).
